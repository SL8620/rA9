### N1. 电池 SOC 与会话进程无关（游程检验）

42 个 run 按录制时间排序，`/battery_state.percentage` 与会话序号的相关系数
**r = +0.002**，首 14.7478、末 14.6913，相邻变号游程 24 次（完全随机期望 ≈20，
单向漂移期望 1–2）。取值在 14.40–15.98 之间随机跳动，42 个 run 42 个不同值。
同期 battery current 均值 −11.5 A，累计放电约 0.13 Ah/run（折算 SOC 应降约 0.9%），
而 run 内 SOC **一个唯一值**（42/42 run）。SOC 既不在 run 内随放电下降，也不在
会话内单调漂移，与 `battery_state.current` 的积分不自洽。

### N2. 同一时刻的电量计与温度计给出相反的会话图景

同一 `/battery_state` 消息里，`temperature` 首值 **29.42 → 41.85 °C** 单调上升，
与会话序号 **r = +0.986**，42 个值互不相同——这正是真实电池/机箱连续升温的形态。
`jointTemperature` 峰值 r = +0.50、由 59.8 升到 91.1 °C，同向。
唯独 SOC（电量计读数）完全无漂移。同一块电池的温度连续升温 12.4 °C、
电量读数却在 35 分钟内原地随机跳动，两路来自同一个 BMS，物理上难以并存。

### N3. 谱系：metadata.yaml 的录制窗口与前批逐微秒相同

本批 42 个 run 的录制墙钟为 **2026-10-21 14:45:05.126313 – 15:37:32.361140**，
跨度 3147.2 s、时长合计 2096.9 s —— 与 `data_review_2026-10-21.md` §8.1 记录的
"新批"（16:49 落盘）**完全相同（含微秒）**。而本批 bag 的落盘时间是
**2026-10-21 19:22**（`metadata.yaml` 仍是 14:45）。两批"独立录制"共享同一组
微秒级录制窗口在物理上不可能；bag 内容确已改变（E2/E3/E4/E5 全部不同），
